# jihyun-transformation

## ✅ 기능 체크리스트

### 📍 기본 구현

- [x] 화면 디스플레이 영역과 컨트롤러 영역 구현

### 📍 화면 영역 (초기 상태 및 표시)

- [x] 초기 화면에 100x100 크기의 사각형 표시
  - [x] 사각형: 100x100 크기, 회색 배경, 검은색 테두리
  - [x] 초기 원점(Pivot): 사각형의 좌하단(left, bottom)
  - [x] 원점 강조 표시: 붉은색 점으로 표시
- [x] 컨트롤러 영역에 사각형 4개 꼭지점의 좌표 표시
  - [x] 좌표는 소수점 두 자리까지 표시

### 📍 컨트롤러 영역 (조작 기능)

#### 1. 이동 (Move)

- [x] X, Y 좌표 입력 필드 제공
- [x] 입력된 좌표로 사각형 이동 기능 구현
  - [x] 이동 기준: 사각형의 좌하단(left, bottom)
- [x] 좌표 입력값은 정수만 허용
- [x] 이동 후 꼭지점 좌표 업데이트 및 소수점 두 자리까지 표시
- [x] 이동 시 애니메이션은 불필요

#### 2. 회전 (Rotate)

- [x] 회전 각도 입력 필드 제공
- [x] 입력된 각도만큼 사각형 회전 기능 구현
  - [x] 회전 기준: 현재 설정된 원점 (초기값은 좌하단)
- [x] 회전 각도는 1도 단위, 정수만 입력 가능 (음수 허용)
- [x] 회전 후 꼭지점 좌표 업데이트 및 소수점 두 자리까지 표시
- [x] 회전 시 애니메이션은 불필요

#### 3. 원점 변경 (Pivot Change)

- [x] 원점 X, Y 좌표 입력 필드 제공
- [x] 회전 중심점 변경 기능 구현
  - [x] 원점 좌표는 사각형 내부/외부 모두 가능 (사각형 기준 상대 좌표)
- [x] 이동 동작 시 원점은 사각형과 함께 이동
- [x] 원점 좌표 입력값은 정수만 허용
- [x] 변경된 원점은 붉은색 점으로 강조 표시
- [x] 회전 시 변경된 원점을 기준으로 회전

## 📝 회고

이번 과제는 캔버스 상에 사각형을 그리고, 회전·이동·원점 변경 등의 동작을 조작할 수 있는 인터랙티브 웹 애플리케이션을 구현하는 작업이었습니다. React와 TypeScript, 그리고 2D Canvas API를 활용하여 과제를 진행했으며, 특히 setTransform과 관련된 좌표계/회전 변환 처리가 주요 구현 포인트였습니다.

✅ **구현 중 중점을 둔 부분**

기능 구현에 있어 가장 중점을 둔 건 정확한 수학적 로직과 사용자 입력 간의 연결이었습니다. 좌표계의 원점을 좌하단으로 잡고 회전·이동을 처리하는 과정은 단순히 캔버스 API를 사용하는 수준을 넘어서, 수학적 좌표 변환과 상태 동기화를 정확하게 처리해야 했기 때문입니다.

React의 useEffect, useState를 기반으로 상태를 관리했고, 사용자 입력은 react-hook-form으로 안정적으로 처리했습니다. 컨트롤러에서 변경된 값은 실시간으로 캔버스에 반영되고, 사각형 꼭짓점의 좌표 또한 소수점 두 자리까지 동기화되도록 신경썼습니다.

🧠 **문제 해결과정에서 배운 점**

처음 접한 canvas 좌표계의 상하 반전과 setTransform의 매트릭스 연산은 꽤 혼란스러웠습니다. 하지만 수학적으로 어떻게 회전/이동/원점 기준 변환이 일어나는지를 하나씩 그림으로 그려가며 정리했고, 이를 기반으로 유틸 함수(canvasDrawing.ts)를 분리하여 재사용성과 테스트 편의성을 높였습니다.

또한, 상태 변경 시마다 canvas를 리렌더링하는 구조를 만들면서 부작용 관리가 얼마나 중요한지 체감했습니다. 불필요한 렌더링을 방지하거나, 입력값이 잘못 들어왔을 때 사용자에게 명확한 피드백을 주는 등의 세심한 UX 처리가 코드 전반의 품질을 크게 좌우한다는 걸 배웠습니다.

🧱 **코드 구조와 스타일**

- 모듈화 구조: features/ 단위로 캔버스, 컨트롤러 기능을 분리했고, 각각 내부에 components, hooks, utils 등의 디렉토리를 구성해 도메인 기반의 구조를 따랐습니다.
- 스타일 관리: styled-components를 활용하여 로직과 UI를 분리하고, 유지보수성과 일관성을 확보했습니다.
- 코드 스타일: ESLint + Prettier, 그리고 import 정렬 플러그인까지 적용해 정적 분석과 코드 포맷팅을 통해 품질을 유지했습니다.
- 네이밍: 기능의 의미가 명확히 드러나도록 파일, 함수, 변수 이름을 직관적으로 작성하는 데에 많은 신경을 썼습니다.

단순히 동작하는 UI가 아니라, 수학적 로직과 시각적 결과가 정확하게 일치하는 애플리케이션을 만드는 경험이었고, 실무에서 그래픽 툴을 다룬다는 것이 어떤 수준의 복잡도인지 간접적으로 체감할 수 있었습니다.
앞으로는 초기 설계 단계에서 상태 흐름과 좌표계 변환 흐름을 좀 더 체계적으로 다이어그램 등으로 정리하고 시작하고 싶습니다.
